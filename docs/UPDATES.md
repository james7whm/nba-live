# 应用更新

设置和托盘提供「检查应用更新」。默认启动 30 秒后检查，此后每 24 小时检查；关闭自动检查后仍可手动检查。使用公开接口，不读取用户的 GitHub／Gitee 账号、密码或令牌。

优先查询 Gitee；镜像落后、缺少适用附件或无法连接时查询 GitHub。发现新版只在设置和托盘显示提示，不弹通知，不抢焦点。可稍后处理、跳过该版本，或点击「下载并更新」。自动检查开关保存设置后生效；跳过版本立即保存，手动检查仍能查看和安装该版本。

更新窗口将主要操作与手动下载渠道分行放置：未发现新版时只显示「关闭」和「检查更新」；有新版才显示「下载并更新」，「跳过此版本」位于底部次要操作区。下载时「稍后」变为「取消下载」。默认 580×680 DIP，支持缩窄至 420 DIP，按钮保持间距与完整文字。

## 下载与安装

- 只安装更高的正式版本。现代版和 net48 兼容版分别匹配附件；不自动切换运行时。源码 ZIP、测试包及预发布均不作为自动更新附件。
- 同时要求正式 ZIP 和同名 `.sha256`。下载失败可尝试另一平台的同版本附件；HTTPS 跳转仅允许发布平台及其下载域名。逐包 SHA256 和清单中的逐文件摘要均需通过校验。
- 下载使用独立连接，不占直播请求通道。窗口内显示进度，关闭窗口取消下载；校验与准备完成后才正常退出主程序。目录不可写、空间不足、文件占用等错误保留原版，提供手动发行版入口。
- 更新后自动启动，保持整体隐藏状态。配置、关注球员和收藏不替换；本次未收藏的会话历史随重启清空。更新窗口参与全局隐藏／恢复。
- 当前包必须带 `NbaLive.package.json` 文件清单。自行修改受管理程序文件会导致校验失败，此时应解压完整包到新目录；用户自行添加的其他文件保留，不覆盖同名冲突文件。

## 恢复与清理

更新工作目录位于 `%LocalAppData%\NbaLive\Updates\<任务编号>`，保存下载包、临时更新程序、旧版备份和日志式恢复记录。新版未在 30 秒内完成启动确认时，更新程序恢复旧版并重启。正常启动发现未完成记录时会尝试恢复；更新期间不会允许同一目录再次启动。

若断电导致程序连启动检查都无法执行，可在对应任务目录运行 `runner\NbaLive.exe --recover-update "完整任务目录\job.json"`；先退出原目录中的应用。`result.txt` 记录该任务结果。恢复仍失败时保留备份，手动解压正式包到新目录，原配置与收藏仍在。

本轮保留恢复文件，不自动删除备份或用户文件。确认新版可用、没有更新正在进行后，可自行清理完成任务目录以回收空间。更新前会检查备份与替换所需空间，空间不足时旧版不退出。SHA256 用于验证传输和内容一致性，并不代替发布者签名；当前尚未接入独立签名密钥。

## 发布者流程

使用构建脚本生成现代完整版、轻量版、兼容版 ZIP 和在线安装 EXE，各附同名校验文件；在线安装器内置与轻量 ZIP 相同的应用文件，不内置运行环境。两个平台上传相同附件，不在镜像端重新打包。同一标签下不替换附件，修订应增加版本号。

正式附件命名：`NbaLive-X.Y.Z-win-x64.zip`、`NbaLive-X.Y.Z-lite-win-x64.zip`、`NbaLive-X.Y.Z-compatibility-preview-net48-win-x64.zip`、`NbaLive-X.Y.Z-online-setup-win-x64.exe`，各附同名 `.sha256`。GitHub 草稿上传全部八个附件并校验后转正式；发布事件触发 Gitee 同步，明确仅复制在线安装 EXE、轻量 ZIP、兼容 ZIP 及校验文件，共六个，不上传现代完整版 ZIP，不删除历史附件。

轻量／在线安装版使用独立的 `modern-lite` 更新类型和文件清单。升级前检查新包运行要求；系统缺少合适组件时保留正在运行的旧版，引导使用在线安装器。在线安装目录属于当前用户，一键更新不需提升应用权限。完整版保持原 `modern` 类型，兼容版保持 `net48`，不自动跨类型升级。

仓库 Actions 的「Build release packages」可输入项目当前版本构建全部形态并下载构建产物。Gitee 同步使用 `scripts/sync_gitee_release.py` 和仓库 Secret `GITEE_TOKEN`；仅从环境读取令牌，不打印响应正文。先核对 Gitee 标签与 GitHub 提交相同，再校验附件并上传；新建为预览，全部匿名下载 SHA256 验证后才转正式。上传或校验失败时保留预览，可在「Sync release to Gitee → Run workflow」输入标签重试；同名内容不同会拒绝覆盖，已有正式发行版不自动补写或替换附件。

v1.2.1 及更早版本没有更新代码，需手动升级至 v1.2.2 一次；此后可通过应用检查后续新版。Gitee 仓库镜像仅同步代码与标签，不自动复制发行附件；仅推送 GitHub 时，国内源可能滞后，应用会继续查询 GitHub。Win7 SP1＋.NET Framework 4.8 和 Win10 实机更新验证仍需完成。
